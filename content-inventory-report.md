## 6. Integration options

The volume is about 14–16 artists, about 17 posts, about 20 partners, and 40–60 images to prepare.

The year-enum change for posts and partners (model, `validator.ts`, `PostForm`, `PartnerForm`, `constants`, and the order and pages that filter by year) is needed **either way**. So is image preparation (resize, convert, rename), because 22 files exceed the limit.

| | Back office forms | One-off import script |
|---|---|---|
| Evidence | `ArtistForm`, `PostForm` and `PartnerForm` exist. Uploads go through `useUploadThing('imageUploader')` (4 MB, 10 files). Texts go through Tiptap, so pasted bilingual text gets visual control. | No `scripts/` folder or seed tooling exists. A script would have to reuse `connectToDatabase` and the server UploadThing API, and match the model shapes. The `IPost` interface has a typo, `frenctText`, while the schema uses `frenchText`. |
| Effort | About 15–20 min per artist and 10 min per post: roughly 8–10 hours of careful entry, about 1.5 days. | Roughly 1 day to write and test, plus building a structured source (the docx is free text, so parsing it is unreliable). It would still need a manual review pass in the back office. |
| Risk | Typing and copy errors, especially RTL issues when pasting Arabic. Low technical risk. | Writing straight to the production database: duplicates, malformed HTML, wrong date offsets, orphan uploads. Little gain at this volume. |

For about 50 records, the forms are the realistic route once the enum fix and image prep are done. A script would only pay off for image preprocessing, run outside the repo.
